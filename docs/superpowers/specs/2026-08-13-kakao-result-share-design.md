# 카카오톡 결론형 결과 카드 공유 설계

## 목표

사용자가 결과 화면에서 카카오톡 공유 버튼을 누르면 개인화된 **B안 결론형 카드**가 이미지·설명·CTA 버튼을 포함한 카카오 피드 메시지로 표시되게 한다. 공유받은 사람은 메시지에서 바로 서비스로 진입할 수 있어야 한다.

## 카드 콘텐츠

- 출력 크기: 800×800 PNG
- 상단: `나의 2026 이직 결론`
- 중앙: AI 리포트의 `one_line_conclusion`을 최대 2줄로 표시
- 보조 문장: 결론을 설명하는 짧은 행동 조언 1개
- 하단: 가장 높은 운세 축의 순위 1개와 `직장인 이직사주` 브랜드
- 제외 정보: 이름, 이메일, 생년월일시, 성별, 회사명, 사용자가 입력한 고민 원문
- 긴 문장은 Canvas에서 줄바꿈하고 최대 길이를 넘으면 말줄임표 처리

카카오 피드 메시지는 다음 카피를 사용한다.

- 제목: `나는 지금 옮겨야 할까?`
- 설명: `내 사주와 실제 고민을 함께 분석한 커리어 리포트입니다.`
- 버튼: `내 이직 결론 확인하기`
- 링크: 현재 운영 서비스의 HTTPS 기본 URL

## 공유 처리 흐름

1. 결과 화면 진입 시 두 Canvas를 모두 렌더링하되 공유용 Canvas는 800×800 해상도로 생성한다.
2. 사용자가 `카카오톡으로 공유`를 누르면 공유용 Canvas를 PNG Blob으로 변환한다.
3. 프런트엔드는 `POST /api/share-card`로 PNG를 전송한다.
4. Pages Function은 파일 형식과 크기를 확인하고 무작위 UUID 키로 R2에 저장한다.
5. API가 공개 HTTPS 이미지 URL을 반환하면 Kakao JavaScript SDK의 기본 피드 템플릿을 호출한다.
6. 카카오톡 피드에는 이미지, 제목, 설명, 서비스 진입 버튼을 표시한다.

Kakao SDK 키가 없거나 이미지 업로드 또는 공유 호출이 실패하면 PNG 파일을 포함한 Web Share API를 시도한다. 파일 공유도 지원되지 않으면 이미지 다운로드와 링크 복사 안내를 제공한다. 사용자가 카카오 공유창을 직접 취소한 경우에는 오류 알림이나 강제 대체 공유를 띄우지 않는다.

## Cloudflare 저장 구조

- R2 바인딩 이름: `SHARE_CARDS`
- 객체 키: `share-cards/<uuid>.png`
- `Content-Type`: `image/png`
- 캐시 정책: `public, max-age=86400`
- 보존 기간: 30일 후 R2 Lifecycle Rule로 자동 삭제
- 공개 조회: `GET /api/share-card/<uuid>.png`
- 업로드 응답: `{ "imageUrl": "https://.../api/share-card/<uuid>.png" }`

R2 버킷 자체는 공개하지 않고 Pages Function이 객체를 조회해 응답한다. 이미지에는 개인정보를 넣지 않지만, 무작위 UUID를 사용해 목록 추측을 어렵게 한다.

## 입력 검증과 남용 방지

- `POST` 요청의 `Content-Type`은 `image/png`만 허용한다.
- 최대 업로드 크기는 1MB로 제한하고 초과 시 `413`을 반환한다.
- PNG 시그니처를 서버에서 확인한다.
- CORS는 운영 도메인과 로컬 개발 주소만 허용하고 `*`를 사용하지 않는다.
- UUID 충돌 시 새 키를 발급한다.
- 이미지 본문과 사용자 입력을 로그에 남기지 않는다.
- Cloudflare Rate Limiting Rule을 업로드 API에 적용할 수 있도록 경로를 독립시킨다.
- Kakao JavaScript 키는 공개 클라이언트 키로만 사용하고 Admin 키는 프런트엔드에 두지 않는다.

## UI 상태

- 기본: `카카오톡으로 공유`
- 이미지 업로드 중: `공유 카드 준비 중...` 및 버튼 비활성화
- 카카오 공유창 호출 후: 기본 상태 복귀
- 업로드 실패: `카카오 공유를 준비하지 못했어요. 이미지로 공유할게요.` 안내 후 파일 공유 시도
- 모든 공유 방식 실패: 이미지 다운로드 후 서비스 링크를 클립보드에 복사

중복 클릭은 진행 상태로 차단한다. 공유 시도 이벤트는 기록할 수 있지만 실제 카카오톡 전송 완료로 해석하지 않는다.

## 설정값

- 프런트엔드: `VITE_KAKAO_JS_KEY`
- 프런트엔드: `VITE_PUBLIC_SERVICE_URL`
- Cloudflare Pages: R2 바인딩 `SHARE_CARDS`
- Kakao Developers: JavaScript SDK 도메인에 운영 Pages 도메인과 최종 커스텀 도메인 등록

설정이 없는 로컬 환경에서도 Web Share 또는 다운로드 대체 경로로 기능을 확인할 수 있어야 한다.

## 테스트

- 카드 렌더링: 결론 줄바꿈, 최대 글자 수, 개인정보 미포함
- 업로드 API: 정상 PNG, 잘못된 MIME, PNG 시그니처 불일치, 1MB 초과, R2 실패
- 공개 조회 API: 정상 조회, 없는 UUID, 올바른 `Content-Type`과 캐시 헤더
- 공유 라우팅: Kakao 성공, 사용자 취소, SDK 미설정, 업로드 실패, Web Share 미지원
- 회귀 검증: 기존 결과 카드 다운로드와 두 Canvas 렌더링 유지
- 수동 검증: Android/iOS 카카오톡 실제 피드 이미지 크롭, 문구 줄 수, 버튼 랜딩

## 완료 기준

- Android와 iOS 카카오톡에서 B안 이미지·설명·CTA가 하나의 피드 카드로 보인다.
- 공유 이미지에 사용자 개인정보가 포함되지 않는다.
- Kakao 또는 R2 설정이 빠진 환경에서도 사용자가 다운로드 가능한 결과 이미지를 얻는다.
- 연속 클릭으로 중복 이미지가 업로드되지 않는다.
