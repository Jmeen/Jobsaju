# 추가 질문 해금 토큰 정합성 설계

## 목표

해금된 AI 리포트에서 사용자가 추가 질문을 제출할 때, 서버가 발급하고 검증할 수 있는 실제 해금 토큰만 전송한다. 개발용 기본 토큰이나 토큰이 없는 저장 세션이 해금된 리포트처럼 동작하지 않게 한다.

## 범위

- 프리미엄 리포트 생성 성공 시 반환된 실제 토큰을 추가 질문 요청에 사용한다.
- 네트워크 예외로 실제 토큰을 받지 못한 경우 결과를 해금 상태로 전환하지 않고 오류를 표시한다.
- 저장된 세션을 복원할 때 실제 토큰이 없는 해금 상태는 무효로 처리한다.
- 정상 토큰을 가진 현재 리포트, 이메일 딥링크, 과거 리포트 선택 흐름은 유지한다.
- 추가 질문 사용 횟수 동기화는 별도 문제이므로 이번 수정 범위에 포함하지 않는다.

## 선택한 접근

클라이언트 상태에서 개발용 기본 토큰을 제거하고 `unlockToken`을 빈 값으로 시작한다. 해금 성공 조건을 “AI 리포트와 실제 토큰을 모두 받은 경우”로 통일한다. 토큰 없이 저장된 세션은 유료 해금 상태로 복원하지 않으며, 네트워크 실패 시 임시 리포트로 조용히 넘어가지 않는다.

서버가 개발용 토큰을 허용하는 접근은 인증을 약화하므로 사용하지 않는다. 추가 질문 버튼에서만 오류를 막는 접근도 잘못된 해금 상태를 그대로 남기므로 사용하지 않는다.

## 데이터 흐름

1. 결제 또는 쿠폰 검증 API가 UUID 해금 토큰을 생성하여 KV에 저장한다.
2. 리포트 생성 API가 같은 토큰을 검증하고 리포트를 저장한다.
3. 클라이언트는 두 요청이 모두 성공한 경우에만 토큰과 리포트를 상태에 저장하고 해금한다.
4. 추가 질문 요청은 저장된 실제 토큰을 `unlock_token`으로 전송한다.
5. 실제 토큰이 없다면 추가 질문 요청을 보내지 않고 리포트 복구 안내를 표시한다.

## 오류 처리

- 프리미엄 리포트 생성 중 네트워크 오류: 화면을 해금하지 않고 재시도 가능한 오류를 표시한다.
- 저장 세션에 토큰 누락 또는 과거 개발용 토큰 존재: 해금 상태로 복원하지 않는다.
- 추가 질문 직전 토큰 누락: 서버 요청 없이 사용자에게 리포트를 다시 열도록 안내한다.
- 서버가 403을 반환하면 서버 메시지를 그대로 표시하여 409 사용 횟수 오류와 구분한다.

## 테스트

- 실제 토큰이 없는 상태는 추가 질문 제출 가능 상태가 아니다.
- 개발용 기본 토큰은 유효한 해금 토큰으로 인정되지 않는다.
- 네트워크 실패 시 임시 리포트로 해금하지 않는다.
- 정상 발급 토큰은 추가 질문 요청에 그대로 전달된다.
- 기존 전체 테스트, 린트, 프로덕션 빌드를 실행한다.
