# 쿠폰 입력 및 PG 연동 대기 결제 디자인

## 목적

숨겨진 프로모션 쿠폰 흐름은 유지하면서 쿠폰 입력 편의성을 높이고, 실제 PG 연동 전 일반 유료 결제가 실행되지 않도록 차단한다.

## 사용자 흐름

1. 사용자가 결제 모달의 `상세 리포트 해금` 제목을 세 번 누르면 기존처럼 프로모션 코드 입력 영역이 열린다.
2. 코드 입력칸은 행에서 가능한 폭을 대부분 차지하고 `적용` 버튼은 필요한 최소 폭만 사용한다.
3. 유효한 쿠폰이 적용되면 기존 `8,900원`은 취소선으로 표시되고 최종 결제 금액은 녹색 `0원`으로 표시된다.
4. 쿠폰 적용 후 `0원으로 전체 풀이 보기` 버튼은 기존 쿠폰 검증 및 리포트 생성 로직을 실행한다.
5. 쿠폰이 없는 `전체 풀이 결제하기 (8,900원)` 버튼은 리포트 생성이나 결제 검증을 호출하지 않고 `현재 PG사 연동 중입니다. 결제 기능은 곧 제공될 예정입니다.` 알림만 표시한다.

## UI 변경

- 쿠폰 행은 가로 `flex` 레이아웃을 유지한다.
- 입력칸에 `flex: 1`과 `min-width: 0`을 적용한다.
- 적용 버튼은 약 60px의 고정 최소 폭과 입력칸보다 작은 패딩을 사용한다.
- 모바일 폭에서도 입력칸이 버튼보다 넓게 유지되어 코드 확인이 쉬워야 한다.
- 기존 모달 색상, 쿠폰 성공색, 버튼 스타일은 유지한다.

## 동작 경계

- 일반 결제 알림은 이메일 유효성 검사보다 먼저 동작한다. 이메일이 비어 있어도 PG 연동 대기 안내만 표시한다.
- 일반 결제 버튼은 클릭 가능한 상태를 유지해야 하므로 `disabled`로 만들지 않는다.
- 쿠폰 검증 API와 쿠폰 사용 횟수 소비 방식은 변경하지 않는다.
- 가격 A/B 로직은 변경하지 않는다. 기본 가격은 기존대로 `8,900원`이며 쿠폰 적용 시 현재 배정 가격에서 `0원`으로 바뀐다.

## 사용자 문구

사용자 화면에 노출되는 `해금` 표현은 다음과 같이 `전체 풀이` 중심으로 통일한다.

- `상세 리포트 해금` → `전체 풀이 보기`
- `해금된 리포트 포함` → `전체 풀이 포함`
- `0원 쿠폰으로 즉시 리포트 무료 해금하기` → `0원으로 전체 풀이 보기`
- `결제 승인 및 리포트 해금 (8,900원)` → `전체 풀이 결제하기 (8,900원)`
- `보관된 해금 리포트` → `보관된 전체 풀이`
- `해금 리포트 불러오기` → `전체 풀이 불러오기`

API 응답, 개발자 로그, 주석, 변수명, 함수명에 포함된 `해금 토큰` 등의 내부 용어는 안정성을 위해 변경하지 않는다.

## 검증

- PG 연동 대기 알림 함수가 승인된 문구로 정확히 한 번 호출되는지 단위 테스트한다.
- 사용자 화면용 결제 문구에 `해금`이 남지 않고 승인된 `전체 풀이` 문구가 사용되는지 테스트한다.
- 쿠폰 미적용 일반 결제 버튼이 기존 `handleUnlock` 대신 대기 알림을 호출하도록 확인한다.
- 쿠폰 적용 상태에서 기존 가격과 `0원`이 함께 표시되고 무료 해금 버튼이 유지되는지 확인한다.
- 모바일 화면에서 쿠폰 입력칸이 적용 버튼보다 충분히 넓은지 시각 확인한다.
- 전체 테스트, 린트, 프로덕션 빌드를 실행한다.

## 제외 범위와 후속 작업

- 실제 PG사 SDK 및 결제 승인 연동
- 쿠폰 API 또는 서버 정책 변경
- 정책 페이지 작성
- 이번 변경과 동시에 `App.tsx`를 대규모로 분리하는 작업

`App.tsx`가 결제, 쿠폰, 리포트, 공유, 입력 흐름을 함께 관리하고 있으므로 후속 작업에서 기능별 컴포넌트와 훅으로 분리하는 리팩터링을 별도 설계한다. 결제 영역은 `PaymentModal`, 쿠폰 상태는 `useCoupon`, 리포트 해금은 `useReportUnlock` 경계가 후보이지만 실제 분리는 별도 승인 후 진행한다.
