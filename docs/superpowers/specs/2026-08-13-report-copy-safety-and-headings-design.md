# 리포트 문구 안전성 및 제목 체계 개선 설계

## 목표

커리어 리포트의 점수 표현, AI 생성 문장, 섹션 제목, 캐릭터 헤더를 일관된 전문 상담 리포트 톤으로 정리한다. 통계로 오인될 수 있는 백분위와 합성 표본 비교를 제거하고, 과거 날짜 추천·외국 문자 혼입·오탈자·과도한 확정 표현이 사용자에게 노출되거나 캐시에 저장되지 않도록 한다.

## 문제의 원인

1. 백분위는 실제 직장인 데이터가 아니라 무작위 생년월일시 20,000건에서 계산한 사주 점수 분포다. 화면과 프롬프트가 이를 `또래 직장인` 비교로 표현해 실제 사용자 집단 통계처럼 보이게 한다.
2. AI 프롬프트에 생성 기준일과 미래 시점 제한이 없어, 이미 지난 달을 준비·지원 시점으로 권할 수 있다.
3. AI JSON을 별도의 언어·금지 표현 검증 없이 그대로 캐시에 저장하고 화면에 표시한다.
4. 프롬프트가 사용자의 구체적 질문을 `그대로 보존`하고 반복 인용하도록 요구해, 짧고 구어적인 원문이 유료 리포트 제목으로 노출된다.
5. 리포트 제목이 챗봇 대화체, 게임형 표현, 전문 보고서 문체를 혼용한다.
6. 캐릭터 이미지의 대체 텍스트와 컬렉션 번호·배지가 연속된 형제 요소라 텍스트 추출 결과가 한 문장처럼 결합된다.

## 설계 원칙

- 사용자가 해석하기 어려운 순위 대신 0~100점과 직관적인 등급을 함께 표시한다.
- 사주 점수는 참고 지표로 표현하고 실제 채용 결과나 가능성을 확정하지 않는다.
- 현재 날짜보다 과거인 달은 미래 행동 시점으로 추천하지 않는다.
- AI 출력은 프롬프트만 신뢰하지 않고 저장 전 결정적 검증을 거친다.
- 사용자 원문은 분석 입력으로 유지하되, 화면 제목은 의미를 보존한 정제 문장으로 표시한다.
- 제목은 짧은 명사형으로 통일하고 한 섹션에 중복되는 제목을 줄인다.
- 장식 이미지는 스크린리더와 텍스트 추출에서 불필요한 문구를 만들지 않는다.

## 점수 표시

### 사용자 노출 규칙

화면, 공유 이미지, AI 프롬프트, 추가 질문 컨텍스트에서 다음 항목을 제거한다.

- `또래 직장인 20,000명과 비교`
- `상위 N%`, `하위 N%`
- 합성 표본 수와 백분위 데이터

점수는 다음 등급과 함께 표시한다.

| 점수 | 등급 |
|---:|---|
| 70~100 | 높음 |
| 55~69 | 보통 이상 |
| 40~54 | 보통 |
| 0~39 | 낮음 |

예시는 다음과 같다.

- `협상운 71점 · 높음`
- `이직운 63점 · 보통 이상`
- `잔류운 33점 · 낮음`

세 축의 대표 방향은 백분위가 아니라 원점수가 가장 높은 축으로 결정한다. 동점일 때는 기존 점수 모델의 축 순서인 이직, 잔류, 협상 순으로 안정적으로 선택한다. 사용자에게 보이는 대표 배지는 `💼 협상운 우세`처럼 표시한다.

기존 합성 분포 생성 코드와 데이터는 사용자 노출 경로에서 분리한다. 다른 기능이 사용하지 않는 것이 확인되면 제거하고, 아직 내부 분석 용도가 있다면 파일은 남기되 UI·공유·AI 입력에서 참조하지 않는다.

## AI 생성 안전장치

### 날짜 기준

프리미엄 리포트와 추가 질문 프롬프트에 다음 값을 전달한다.

- 생성 기준일: `YYYY-MM-DD`
- 기준 시간대: `Asia/Seoul`

프롬프트에는 다음 규칙을 명시한다.

- 행동 시점을 추천할 때 생성 기준일 이전의 날짜나 달을 미래 계획으로 제시하지 않는다.
- 과거 시기를 언급해야 한다면 이미 지난 시점임을 명시하고, 실제 행동 계획은 현재 이후로 다시 제시한다.
- `언제 지원할까요`처럼 시점을 묻는 질문은 현재 이후의 가장 가까운 후보부터 답한다.

### 문체와 사실성

다음 원칙을 프리미엄 리포트와 추가 질문에 공통 적용한다.

- 불합격 원인은 `원인입니다`로 확정하지 않고 `영향을 주었을 가능성이 있습니다`와 확인 방법을 함께 제시한다.
- `CEO가 될 수 있습니다`, `합격률이 올라갑니다`, `가장 빠른 길입니다`처럼 미래 결과를 보장하지 않는다.
- 특정 업종·직무 추천은 사용자 입력에서 직접 이어지는 근거가 있을 때만 제시한다.
- 연봉 범위는 사주 점수로 정당화하지 않고 시장 연봉, 총보상, 직무 범위, 기업 밴드를 먼저 확인하도록 한다.
- `몸값`, `서류를 뿌리다`, `진짜 CEO`, `커리어 골`, `크리처`처럼 전문 리포트 톤을 해치는 표현을 사용하지 않는다.
- `정차`, `높음 협상운` 등 확인된 오류 표현을 금지한다.
- 리포트 본문은 한국어를 기본으로 하며 직무 약어처럼 필요한 라틴 문자만 허용한다.

### 질문 제목 정제

사용자의 질문 원문은 분석 입력으로 보존하지만 `personal_answer.question`에는 원문 복사가 아니라 의미를 보존한 정제 질문을 생성한다.

예:

- 입력: `합격이 안됨`
- 표시: `이직 지원이 계속 불합격하는 이유와 개선 방향`

정제 제목은 존댓말 문장 대신 짧은 명사형으로 만들고, 새로운 사실이나 사용자가 묻지 않은 목표를 추가하지 않는다.

### 출력 검증과 재시도

모델 응답을 캐시에 저장하기 전에 JSON을 파싱하고 전체 문자열을 검사한다.

검증 실패 조건:

- 아랍 문자, 키릴 문자, 데바나가리 등 허용하지 않은 문자권 혼입
- `정차`, `높음 협상운`, `커리어 골인` 등 명시적 금지 표현
- 필수 JSON 필드 누락 또는 문자열 타입 위반
- 정제 질문 제목이 비어 있음

첫 검증 실패 시 기존 답변과 검증 사유를 포함한 교정 요청으로 한 번만 재생성한다. 두 번째도 실패하면 캐시에 저장하지 않고 명확한 생성 오류를 반환한다. 사용자 질문 원문과 개인정보는 오류 메시지나 서버 로그에 포함하지 않는다.

## 제목 체계

화면 고정 제목은 다음으로 통일한다.

| 기존 | 변경 |
|---|---|
| 이번 흐름의 결론 | 핵심 결론 |
| 또래 직장인 20,000명과 비교 | 현재 가장 강한 흐름 |
| 선택지 비교 | 커리어 선택지 비교 |
| 어느 방향에 힘이 실리는지 | 이직·잔류·협상 점수 |
| 지금 할 일 | 가장 먼저 할 일 |
| 판단 근거 | 사주 해석의 기초 정보 |
| 내 사주 명식 | 사주 명식 |
| 입력 내용을 이렇게 이해했어요 | 커리어 목표와 현재 고민 |
| 이번 결정에서 따로 볼 조건 | 이번 결정의 핵심 변수 |
| 업무 성향 | 업무 성향과 강점 |
| 잘하는 방식 | 강점이 발휘되는 방식 |
| 주의할 패턴 | 주의가 필요한 업무 패턴 |
| 세 가지 선택지 | 이직·잔류·협상 비교 |
| 다음 환경 | 나에게 맞는 조직 환경 |
| 실행 계획 | 이번 주 실행 계획 |
| 먼저 할 일 | 이번 주 우선 과제 |
| 지금은 피할 일 | 피할 행동 |
| 내 질문에 대한 답 | 핵심 질문 분석 |
| 상담사의 마지막 조언 | 마무리 제언 |
| 앞으로 6개월 이직 로드맵 | 향후 6개월 커리어 로드맵 |
| 내 사주 오행과 오피스 능력치 | 오행 기반 업무 성향 지표 |
| 내 사주의 밸런스 풀이 | 오행 균형 해석 |
| 추가 질문 / 내 추가 질문과 답변 | 추가 질문 답변 |
| 내 결과 카드 / 내 이직운 캐릭터 & 백분위 카드 | 공유용 커리어 카드 |

AI가 생성하는 각 섹션의 상세 제목은 계속 사용할 수 있지만 `CEO 성장 발판`, `최적`, `타고난 운명`처럼 단정적인 표현은 금지한다.

## 캐릭터 헤더

- 캐릭터 이미지는 장식 요소로 취급해 `alt=""`를 사용한다.
- 섹션에는 캐릭터 이름을 포함한 접근 가능한 레이블을 별도로 둔다.
- 컬렉션 번호와 우세 배지는 서로 다른 요소로 유지하되, 텍스트 추출 시 의미가 분리되도록 구조와 접근성 속성을 정리한다.
- `목(木) 크리처 · 협상운 우세형`은 `목(木) 개척자형 · 협상운 우세`처럼 표시한다.
- 컬렉션 번호는 보조 정보로 캐릭터명 아래에 배치하고, 우세 배지는 점수 등급과 중복되지 않게 한다.

권장 표시 순서:

1. `큰 나무의 개척자`
2. `목(木) 개척자형 · 협상운 우세`
3. `No. 01 / 10`

## 기존 저장 리포트

화면 고정 제목과 점수 표시는 기존 저장 리포트에도 즉시 적용한다. 기존 AI 본문은 의미를 임의로 재작성하지 않는다. 새로 생성되는 리포트부터 강화된 프롬프트와 검증을 적용하며, 잘못 생성된 기존 리포트는 새 버전 캐시 키를 사용해 재생성할 수 있도록 리포트 버전을 올린다.

이메일 조회에서 구버전 리포트가 발견되면 구버전임을 식별할 수 있는 메타데이터를 반환한다. 유효한 해금 토큰과 AI 설정이 있으면 새 버전 생성 경로를 사용하고, 재생성이 불가능하면 기존 본문을 그대로 반환하되 화면 고정 문구만 새 체계로 표시한다.

## 테스트 전략

1. 점수 등급 경계값 0, 39, 40, 54, 55, 69, 70, 100을 단위 테스트한다.
2. 대표 축이 원점수 최댓값으로 결정되고 동점 규칙이 안정적인지 검사한다.
3. 사용자 노출 모델과 공유 카드에 `상위`, `하위`, `20,000`, `백분위`가 포함되지 않는지 검사한다.
4. AI 요청 데이터와 프롬프트에서 백분위를 제거했는지 검사한다.
5. 프리미엄 및 추가 질문 프롬프트에 생성 기준일, `Asia/Seoul`, 과거 날짜 추천 금지 규칙이 포함되는지 검사한다.
6. 외국 문자와 금지 표현이 첫 응답 검증을 실패시키고, 정상 한국어 응답은 통과하는지 검사한다.
7. 교정 재생성이 한 번만 수행되고 실패 결과가 캐시에 저장되지 않는지 검사한다.
8. `합격이 안됨` 같은 원문이 정제 질문 제목으로 표시되는 계약을 검사한다.
9. 화면 제목 상수에서 기존 표현과 가벼운 금지 표현이 사라졌는지 검사한다.
10. 전체 테스트, 린트, 타입 검사, 프로덕션 빌드를 실행한다.
11. 결과 화면에서 캐릭터 헤더, 점수 카드, 프리미엄 섹션, 추가 질문, 공유 카드를 시각적으로 확인한다.

## 범위 밖

- 사주 점수 자체의 산식 변경
- 캐릭터 이미지 교체
- 리포트 전체 레이아웃 재설계
- 과거 캐시 본문의 자동 문장 치환
- 결제 및 해금 정책 변경
