# 추가 질문 이해·라우팅·안전 정책 설계

## 목표

사용자의 표현이 예상한 키워드와 다르거나 여러 의도가 섞여 있어도 질문의 핵심을 먼저 정리하고, 그 질문에 필요한 커리어 정보만 사용해 직접 답한다. 커리어 범위를 벗어나거나 위험한 질문은 답변을 생성하지 않고 안전한 재질문 예시를 제공한다.

## 핵심 원칙

- 질문 인용이나 전체 사주 총평으로 시작하지 않는다.
- 질문에서 요구하는 답변 형태를 먼저 맞춘다: 시점, 선택, 금액 기준, 방법, 가능성, 비교.
- 사주 지표는 질문에 관련된 근거만 사용하며 현실 조건보다 앞세우지 않는다.
- 현재 직무·경력 목표·고민을 연결하되 입력에 없는 경력이나 업종을 지어내지 않는다.
- 복합 질문은 핵심 질문 하나와 보조 질문들로 나누어 빠뜨리지 않고 답한다.
- AI 호출은 추가하지 않는다. 질문 분석과 답변 생성을 한 번의 호출에서 처리한다.

## 처리 흐름

1. 클라이언트와 서버가 길이 및 공백을 검증한다.
2. 서버의 결정적 가드가 명백한 차단 질문과 프롬프트 조작을 먼저 판정한다.
3. 허용된 질문은 Gemini에 사주 요약·사용자 상황과 함께 전달한다.
4. Gemini는 내부적으로 질문을 다음 항목으로 구조화한 뒤 답변한다.
   - 정리된 핵심 질문
   - 주 의도와 보조 의도
   - 답변 형태
   - 비교 대상
   - 사용자가 명시한 제약조건
   - 답변에 필요한 현실 정보와 사주 신호
5. 서버는 반환 JSON의 구조와 답변 길이를 검사한다.
6. 서버 오류나 로컬 개발 환경에서는 동일한 범위 판정과 다중 의도 분류를 사용하는 로컬 폴백을 출력한다.

## 질문 의도

단일 첫 매치 방식 대신 점수 기반 다중 의도 분류를 사용한다. 주 의도는 가장 구체적이고 점수가 높은 항목이며, 함께 감지된 항목은 보조 의도로 보존한다.

- `industry`: 업종·산업군·IT 유지·도메인 이동
- `role`: 직무·직책·커리어 방향 전환
- `timing`: 지원·퇴사·이동 시점
- `offer`: 오퍼·입사 제안 수락
- `salary`: 연봉·처우·보상 협상
- `wait`: 승진·잔류·약속 대기
- `quit`: 선퇴사·휴식·번아웃
- `people`: 상사·동료·조직 갈등
- `compare`: 둘 이상의 선택지 비교
- `preparation`: 이력서·면접·포트폴리오·준비 순서
- `general`: 위 유형에 해당하지 않지만 커리어 범위 안인 질문

예를 들어 “IT를 유지하면서 연봉을 올릴지 다른 업종으로 갈지”는 `industry`를 주 의도, `salary`와 `compare`를 보조 의도로 처리한다.

## 답변 가능 범위

다음은 넓게 허용한다.

- 이직, 잔류, 퇴사, 휴식, 재취업
- 직무·직책·업종·산업군·창업·프리랜서 전환
- 연봉·처우·계약·협상
- 면접·서류·포트폴리오·지원 전략
- 승진·성과평가·조직 개편
- 상사·동료·리더·문화·업무 관계
- 업무 적성·환경·성장 경로·워라밸

질문이 모호하지만 커리어 범위라면 차단하지 않는다. 현재 입력으로 답할 수 있는 부분을 답하고, 판단에 필요한 현실 정보 한두 가지를 조건으로 밝힌다.

## 차단 정책

다음 질문은 AI에 보내기 전에 서버에서 차단한다.

- 로또 번호, 주가·코인 가격처럼 금전적 결과를 확정적으로 예측하도록 요구
- 수명·사망 시기·질병을 진단하거나 치료 결정을 요구
- 범죄, 보복, 괴롭힘, 자해 또는 타해를 실행하는 방법 요구
- 특정인의 속마음·불륜·배신·미래 행동을 사실로 단정하도록 요구
- 시스템 프롬프트·API 키·내부 규칙 공개 또는 기존 규칙 무시 요구
- 커리어와 관련 없는 일반 지식·연애·시험 정답·숙제 대행 질문

차단 응답은 비난하지 않는다. 답할 수 없는 이유를 한 문장으로 밝히고, 커리어 관점으로 바꾼 재질문 예시 하나를 제공한다. 안전 위기 표현이 감지되면 운세 풀이 대신 즉각적인 주변 도움과 긴급 지원을 안내한다.

## AI 답변 계약

Worker는 다음 JSON만 허용한다.

```json
{
  "question_analysis": {
    "summary": "사용자가 실제로 알고 싶은 것",
    "primary_intent": "industry",
    "secondary_intents": ["compare"],
    "answer_mode": "choice",
    "constraints": ["현재 IT 경력 활용"]
  },
  "answer": "질문에 직접 답하는 2~4개 문단"
}
```

클라이언트에는 기존 계약을 유지해 `answer`만 표시한다. 서버는 `answer`가 문자열인지, 200~900자인지, 금지된 상투 서론이 없는지 검사한다. 구조가 잘못되면 추가 과금 재시도 없이 안전한 서버 폴백을 반환한다.

## 답변 구성

허용된 답변은 다음 순서를 따른다.

1. 첫 문장: 질문에 대한 직접 답 또는 우선순위
2. 이유: 사용자 경력·목표·현실 조건
3. 관련 있는 사주 신호만 보조 근거로 사용
4. 확인할 제약조건과 다음 행동

업종·직무 질문에서는 월운과 협상 점수를 기본적으로 사용하지 않는다. 사주만으로 특정 회사나 업종의 성공을 확정하지 않고, 전환 가능한 역량·공고 요구조건·시장 반응을 검증하도록 안내한다.

## 로컬 폴백

로컬 폴백은 `QuestionAssessment` 결과를 받는다.

```ts
interface QuestionAssessment {
  allowed: boolean;
  refusalReason?: 'unsafe' | 'high_stakes' | 'private_prediction' | 'prompt_injection' | 'out_of_scope';
  primaryIntent: FollowUpIntent;
  secondaryIntents: FollowUpIntent[];
  answerMode: 'timing' | 'amount' | 'choice' | 'method' | 'possibility' | 'explanation';
}
```

`industry` 폴백은 현재 직무와 목표가 있으면 이를 직접 언급한다. 입력이 없으면 구체 업종을 지어내지 않고, 인접 업종 판단 기준과 현직자 인터뷰·공고 비교 같은 검증 행동을 제시한다.

## 오류 처리와 사용권

- 차단된 질문은 추가 질문 사용 횟수를 소진하지 않는다.
- 서버/모델 오류도 사용 횟수를 소진하지 않는다.
- 정상 답변을 생성한 뒤에만 KV에 사용 완료를 기록한다.
- 이미 저장된 구버전 답변은 자동 변경하지 않는다. QA에서는 새 리포트 세션으로 재시험한다.

## 테스트

질문 케이스 테이블을 사용해 다음을 검증한다.

- 업종: “IT를 유지할까요?”, “어떤 산업군이 맞나요?”, “금융 도메인으로 옮길까요?”
- 복합: “오퍼를 받을지 승진을 기다릴지”, “퇴사 후 창업할지 재직하며 준비할지”
- 간접 표현·오타·구어체: “딴일 해볼까”, “여기 더 다녀?”, “연봉 얼마 질러?”
- 현실 제약: 생활비, 출퇴근, 육아, 재택, 연봉 하락 허용 범위
- 허용 경계: 모호하지만 커리어 관련 질문
- 차단: 로또, 코인 확정 예측, 사망·질병, 보복·불법, 타인 속마음, 프롬프트 공개, 무관 질문
- 프롬프트 주입 문장이 포함돼도 질문 데이터로만 취급
- 차단·오류 시 사용권이 소진되지 않음
- 업종 질문 답변에 무관한 협상운·이번 달 월운이 섞이지 않음

## 범위 제외

- 추가 질문 횟수 확대
- 대화형 다중 턴 상담
- 외부 채용공고나 연봉 데이터의 실시간 검색
- 의학·법률·투자 전문 상담
