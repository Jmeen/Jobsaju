# 추가 질문 대기 경험 및 응답 서식 개선 설계

## 목표

추가 질문을 제출한 사용자가 서버 응답을 기다리는 동안 진행 중임을 분명히 이해하게 하고, AI 응답의 `**강조**` 표기를 화면에서 자연스러운 굵은 글씨로 표시한다.

## 현재 문제와 원인

- 추가 질문 요청 중 `isFollowUpLoading` 상태는 버튼 문구와 입력 비활성화에만 사용된다. 요청이 수십 초 걸리면 사용자는 화면이 멈췄다고 느낄 수 있다.
- 추가 질문 답변은 문자열을 일반 `<p>` 요소에 직접 출력한다. 따라서 마크다운의 `**...**`가 해석되지 않고 원문 그대로 노출된다.

## UX 설계

질문 제출 직후 입력 폼 전체를 같은 카드 안의 대기 패널로 교체한다. 카드 위치와 크기 변화는 최소화하여 사용자가 현재 작업의 맥락을 잃지 않게 한다.

대기 패널은 다음 요소를 포함한다.

- 작은 회전형 로더와 `답변을 준비하고 있어요` 제목
- 기존 디자인 시스템과 같은 진행 트랙 애니메이션
- 순환 안내 문구 3개
  1. 질문의 핵심을 정리하고 있어요
  2. 사주 흐름과 현재 상황을 대조하고 있어요
  3. 실행 가능한 답변으로 다듬고 있어요
- `보통 20~40초 정도 걸릴 수 있어요. 창을 닫지 말아 주세요.` 안내
- 스크린리더가 상태 변화를 읽도록 `role="status"`와 `aria-live="polite"` 적용

요청 성공 시 대기 패널을 답변 스레드로 교체한다. 요청 실패 시 기존 로컬 대체 답변 정책을 유지한다. 중복 제출 방지를 위해 로딩 중 입력과 버튼은 렌더링하지 않는다.

## 응답 서식 설계

외부 마크다운 패키지는 추가하지 않는다. 추가 질문 답변에 필요한 범위만 처리하는 작은 파서를 별도 유틸리티로 둔다.

지원 범위:

- 빈 줄로 구분되는 문단
- `**텍스트**` 형태의 굵은 강조
- `- 항목` 또는 `* 항목` 형태의 순서 없는 목록
- 줄바꿈

지원하지 않는 HTML 태그, 링크, 이미지, 코드 실행 요소는 모두 일반 텍스트로 출력한다. React 요소로만 조립하여 `dangerouslySetInnerHTML`은 사용하지 않는다. 잘못 닫힌 `**`는 원문 텍스트로 보존한다.

## 컴포넌트 경계

- `FollowUpLoading`: 대기 패널과 순환 문구를 담당한다.
- `FormattedAnswer`: 제한된 응답 서식을 안전한 React 요소로 렌더링한다.
- 기존 `handleFollowUpSubmit`: 요청과 상태 변경만 담당하며 API 계약은 바꾸지 않는다.

작은 앱 구조를 유지하기 위해 두 UI 컴포넌트는 추가 질문 전용 파일에 배치하며, 파싱 로직은 독립 함수로 분리해 단위 테스트가 가능하게 한다.

## 상태 흐름

1. 사용자가 유효한 질문을 제출한다.
2. `isFollowUpLoading=true`가 되며 입력 폼 대신 대기 패널이 표시된다.
3. 대기 중 안내 문구가 일정 간격으로 순환한다.
4. 성공 또는 로컬 대체 답변 생성 후 `followUp`이 저장된다.
5. `isFollowUpLoading=false`가 되고 포맷된 답변 스레드가 표시된다.

## 오류 처리

- 검증 오류는 기존처럼 요청 전에 입력 폼에서 표시한다.
- HTTP 409는 기존 1회 사용 안내를 유지한다.
- 그 밖의 서버 및 네트워크 오류는 현재 정책대로 로컬 대체 답변을 표시한다.
- 컴포넌트가 언마운트되면 순환 문구 타이머를 정리한다.

## 테스트

- 굵은 강조가 텍스트 토큰과 강조 토큰으로 분리되는지 검증한다.
- 여러 강조 구문, 닫히지 않은 강조 구문, 일반 별표가 안전하게 보존되는지 검증한다.
- 문단과 목록이 올바른 블록 구조로 변환되는지 검증한다.
- 로딩 문구 순환 함수가 세 단계를 반복하는지 검증한다.
- 전체 단위 테스트, 린트, 프로덕션 빌드를 실행한다.
- 브라우저에서 추가 질문 제출 후 대기 패널과 완료 답변의 굵은 표시를 직접 확인한다.
