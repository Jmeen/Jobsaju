# SAJU ENGINE SPEC — 초기 설계

## 1. 목적

AI가 사주를 “창작”하지 않도록 한다.

시스템은 두 레이어로 분리한다.

### Layer 1 — Deterministic Saju Engine
입력:
- 생년월일
- 출생시간
- 양/음력
- 성별
- 기준 시각/시간대

출력 예:
- 사주 원국
- 오행
- 십성
- 대운
- 세운
- 월운
- 직업/이동 관련 계산 가능한 feature

같은 입력은 항상 같은 계산 결과를 반환한다.

### Layer 2 — Interpretation Engine
입력:
- deterministic 사주 feature
- 현재 커리어 상황
- 가장 큰 고민
- 가장 알고 싶은 질문

출력:
- 이직/잔류/협상 점수
- 설명
- 시기별 행동 가이드
- 상세 리포트

---

## 2. 중요 설계 원칙

### 점수와 서술 분리

가능하면:
- 점수: 규칙 기반
- 설명: AI 기반

AI가 숫자를 마음대로 생성하지 않게 한다.

---

## 3. Career Feature 후보

정확한 명리 규칙은 구현 전에 별도 검증 필요.

검토할 영역:
- 관성
- 재성
- 인성
- 식상
- 비겁
- 합/충/형/파/해
- 대운/세운 변화
- 이동성/변화성 관련 전통적 해석
- 직업 및 조직 관련 신호

중요:
이 문서는 제품 구조만 정의한다.
구체 명리 규칙은 **별도 검증된 룰셋**으로 작성해야 한다.

---

## 4. 점수 구조 예시

실제 가중치는 미확정.

```text
move_score
stability_score
negotiation_score
compensation_score
organization_score
```

최종:
```text
job_change_score
stay_score
negotiation_score
```

점수는 내부 feature에서 계산하고,
AI는 점수의 의미를 설명한다.

---

## 5. AI Prompt 원칙

AI에게 전달:
- 사주 계산 결과
- 점수
- 관련 feature
- 사용자의 현재 상황
- 사용자의 핵심 고민

AI에게 금지:
- 원국 재계산
- 새로운 점수 생성
- 사주 feature 변조
- 확정적인 미래 예언
- 법률/재정/의료 결정 대행

---

## 6. 개인정보

가능하면:
- 생년월일 등 입력값은 로컬 처리 우선
- 서버 전달 시 최소화
- 로그에 원문 출생정보를 남기지 않도록 설계
- 공유 카드에는 생년월일 미표시
